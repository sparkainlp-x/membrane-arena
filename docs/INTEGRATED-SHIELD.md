# The integrated shield: the reference channel is now in play

The reference channel (PR #16) proved the shield could have grounds, but it
was Lab-only: the in-game shield still voted 2-of-3 without consulting it.
This change integrates the reference channel into the in-game shield
(`game.js` `shieldCommit`, `referenceConfirm`).

## How it works

When the in-game shield would commit — 2 of 3 membranes agree on a
declaration — it first consults the reference channel before committing. The
reference check takes M = 20 independent samples from the environment
without the disturbance (the true pattern, if one is planted, plus noise —
never the disturbance) and confirms only when the declared vector's mean
energy ratio reaches the game's own declaration threshold
`scaledThreshold(0.5, 32, sigma)` = 3.91. Same threshold and M as the Lab
reference probe (`lab.js` `referenceProbe`).

- If the reference confirms, the shield commits as before.
- If it does not confirm, the shield abstains and play continues.
- The 2-of-3 vote is preserved as the trigger. The reference is a gate on
  the commit, not a replacement for voting.

## Design decisions

- **Separate RNG stream.** The reference channel draws from its own seeded
  stream (`createContest` `refRng`, `membrane-arena/v1/<seed>/reference`),
  independent of the membranes' stream. Consulting the reference never
  perturbs the game's own randomness — only the commit decision changes.
  This is what "independent witness" means in the implementation: the
  reference channel does not share the membranes' random numbers, and it
  never sees the disturbance.
- **Clean samples by design.** The game engine knows the true pattern, so
  the reference samples are generated from it (`noisy(pat, sigma, rng)` when
  a pattern is planted, pure noise `rvec` otherwise). The disturbance is
  never in the reference samples. (The leak check, PR #17, showed the
  grounds tolerate up to a half-strength leak; the integration uses clean
  samples by design, so no leak is present.)
- **Fixed threshold.** The reference threshold is `scaledThreshold(0.5, n,
  sigma)` — the default threshold parameter — matching the Lab reference
  probe at the repository starting parameters. It does not track the
  membranes' evolved `th`, which would let the gate drift with the contest.
- **Recorded in the episode.** Each episode record now carries
  `refChecked` (the shield reached 2-of-3 and consulted the reference) and
  `refConfirmed` (the reference confirmed). A commit is always
  reference-confirmed; a checked-but-unconfirmed episode never commits
  (`passed` null, `dropped` true, `outs` empty).

## Measured behaviour (scripts/integrated-shield-check.js)

K = 500 episodes per arm, real `episode()`, real `shieldCommit`, default
membrane params (th 0.5, c 0.05, g 1.0), M = 20, threshold 3.91:

| arm      | 2-of-3 pass | commit rate | confirm \| pass | passMatch |
|----------|-------------|-------------|-----------------|-----------|
| signal   | 95.6%       | 94.2%       | 98.5%           | 471/500   |
| artifact | 96.2%       | 0.0%        | 0.0%            | 0/500     |

The integrated shield preserves the Lab result in play: it commits on the
signal 94.2% of the time and on the artifact never. The 2-of-3 vote alone
still passes the artifact 96.2% of the time — the gate, not the vote, is
what gives the shield grounds. The check (`node
scripts/integrated-shield-check.js`) passes when the signal commit rate is
above 50% and the artifact commit rate is below 50%.

## What changed in the game

The shield now abstains on declarations the reference does not confirm.
In normal play that means false commits — membranes agreeing on noise —
are (nearly) eliminated: the reference sees only noise in a noise episode,
so it does not confirm. True commits drop slightly (the reference confirms
a real pattern ~98.5% of the time it is asked). The net effect on the game
score is positive (precision rises to ~1.0), but the exact contest numbers
changed — see the golden test below.

## Golden numbers

The golden test (`tests/game.test.js`, "golden: full contests reproduce
the exact v0.1.0 numbers") pins the exact outcomes of two contests. Those
numbers changed with this integration, because the shield now gates
commits on the reference: some commits that used to happen no longer do,
which changes outT/outF, the scores, the (1+1)-ES acceptance, and the
final parameters. The new numbers are the correct ones for the integrated
shield; they were regenerated by running the test, not chosen. Old
challenge links no longer play the same contest — that is the honest
consequence of the shield now having grounds, and it is the point of this
change.

(Numbers from the test run, integrated shield.)

| seed         | T  | F | score     | final th / g                                          |
|--------------|----|---|-----------|-------------------------------------------------------|
| golden1      | 17 | 3 | 47.378472 | 0.330000/0.940000 0.388689/0.594087 0.330000/0.940000 |
| d2026-10-24  | 43 | 0 | 91.590712 | 0.444596/0.867208 0.498952/1.194003 0.527778/0.988014 |

(Old, pre-integration numbers were golden1: T 41, F 7, score 81.770833;
d2026-10-24: T 45, F 2, score 93.131049.) The golden1 drop is the gate
working: that contest's membranes evolved to low th (0.33), declaring on
weak evidence, and the reference (fixed threshold 3.91) rejects those weak
declarations — in that contest the reference confirmed only 41.7% of the
planted-episode agreements it was asked about, against 93.5% for
d2026-10-24, whose th stayed near 0.5. The ensemble at the repository
setup (n = 40, shield on) shows the typical effect, not the golden1
extreme: T mean 39.98 (baseline 42.15, intervals overlap), F mean 0.50
(baseline 3.95), precision mean 0.987 (baseline 0.915).
